# v0.4 plan

## What the leak changes

v0.1 cannot be the base. Its training split (`ids-input/build/serif-ids/train.jsonl`) contains **4,274 of
the 4,752** characters in the current han2ids test set, 89.9%. Its 84.44% and the 90.17% v0.1+v0.3
oracle are not held-out numbers. The v0.1→v0.2 improvement comparison is contaminated for the same
reason. v0.2 and v0.3 use a disjoint character split and remain clean; v0.3 is the baseline at 82.88%.

## Stages

### 0. Evaluation

- Keep test characters disjoint; tune only on `build/font-v03/val`.
- Report exact, same-tree, variant and valid overall and per font.
- Report the 1,205 shared characters separately.
- Use char-cluster paired bootstrap for gains; do not select on test.

### 1. v0.4a

Continue `models/han2ids-v0.3.pt` on `build/font-v03` for 6 epochs.

- Labels: `han2ids.status.gold`, so per-font overrides apply.
- AdamW: encoder 5e-5, decoder 2.5e-4, wd 0.05, clip 1.0, bf16, batch 32.
- 5% warmup, cosine; best val exact.
- Script: `scripts/train_fonts_v4.py` → `models/han2ids-v0.4a.pt`.

Gate: +0.5 exact on val over v0.3, else keep v0.3.

### 2. v0.4j

Continue v0.4a on the 86,406 Jigmo train rows for 3 epochs.

- Encoder 2e-5, decoder 1e-4, same loss.
- Script: `scripts/train_fonts_v4j.py` → `models/han2ids-v0.4j.pt`.

Gate: +1.0 exact on the Jigmo val slice, paired by character. Add a 3-class font probe on the frozen
encoder; route Jigmo to v0.4j, Noto/IPAmj to v0.4a. Report oracle-font routing and probe confusion.

### 3. Clean reranker (optional)

Only over v0.3, v0.4a and v0.4j — never v0.1. Candidates from beam search, features from confidence,
agreement, tree distance and predicted font; train on half of val, grouped by character. This is only
worth it if the clean candidate union is well above v0.4a and the val gain clears 0.3.

## Consultation

  clean reranker. Rejects v0.1 initialization.
- **muse**: recommended fine-tuning v0.1 for eight epochs. That report did not account for the split
  overlap and is superseded.
- astra, fable and opus skipped at the quota gate; ember returned empty; grok hit an OpenRouter 402.
  No independent confirmation beyond these two.

## Resources

The `batch.slice` cgroup is at 16.5/17.2 GB from other services, so the training launch was stopped
before it could make progress. The scripts are prepared; run v0.4a when the slice has room.

## Result

v0.4a finished six epochs from v0.3. On the clean test:

| | exact | same tree | valid |
| --- | ---: | ---: | ---: |
| v0.3 | 82.88% | — | 100% |
| v0.4 | **84.54%** | 87.79% | 100% |

Per font: Noto 93.32%, IPAmj 84.63%, Jigmo 81.80%.

The Jigmo specialist was not shipped: its first runs started from an unloaded head and did not beat
this model. v0.4 is the clean continuation.
